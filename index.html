The Traffic Each Kind of Parallelism Creates

Large-model training splits work along several axes at once, and each axis puts a different kind of data on a different kind of link. What a compute-in-transit module could act on depends on which traffic it sees.

ParallelismWhat crosses the linkHow oftenTypical link
Data parallel (DDP)Gradients, summed across replicas (all-reduce)Every optimiser stepInfiniBand or Ethernet between nodes
FSDP / ZeRO-3Weight shards (all-gather) before use; gradients (reduce-scatter) after the backward passEvery layer, forward and backward, every stepNVLink in a node, InfiniBand between nodes
Tensor parallelActivations and their gradients, combined by all-reduceEvery layer, forward and backwardNVLink, inside one node
Pipeline parallelActivations forward, activation gradients backwardAt each stage boundary, per micro-batchInfiniBand between nodes
Sequence / context parallel (incl. ring attention)Key and value blocks passed round a ring of devicesEvery attention layerNVLink or InfiniBand
Expert parallel (MoE)Tokens to their experts and back (all-to-all)Every MoE layer, twiceNVLink or InfiniBand
  • The bulk transfer is the data-parallel sync: once per step, one model-sized buffer per worker (slide 02). It is also the only traffic that can cross a data centre boundary without stalling every layer, which is where low-communication methods act (slide 06).
  • Per-layer traffic is latency-critical: tensor-parallel and ring-attention exchanges sit on the critical path of each layer, so anything inserted on those links must add little delay.
  • Sources: Megatron-LM for tensor parallelism (Shoeybi et al., arXiv:1909.08053); ZeRO (Rajbhandari et al., arXiv:1910.02054) and PyTorch FSDP (Zhao et al., arXiv:2304.11277); GPipe (Huang et al., arXiv:1811.06965); ring attention (Liu, Zaharia and Abbeel, arXiv:2310.01889); GShard for MoE all-to-all (Lepikhin et al., arXiv:2006.16668).

03

Ring All-Reduce Arithmetic

N workers each hold a buffer of B bytes and all need the sum. Split each buffer into N chunks and arrange the workers in a ring.

  • Bandwidth-optimal: the bytes each worker sends approach 2B as N grows, independent of N, so adding workers does not add traffic per link. That is why results.md's 8- and 64-worker columns differ by only about an eighth (28.10 against 31.62 GB for Llama-3-8B).
  • The cost is latency: 2(N−1) sequential steps, each paying the link's latency. Collective libraries switch to tree or hierarchical schemes for small messages and large N; the byte count of the bulk sync stays near 2B.
  • The arithmetic is tiny. The reduce-scatter adds each value once per hop: one add per BF16 value, 0.5 operations per byte (results.md section 2). The work is moving the bytes, not summing them.
  • Where a link module sits matters: in a ring, each link carries a partial sum from one neighbour, so a module on that link sees one stream. It can transform or compress that stream; it cannot sum workers whose data never pass through it (slide 05).

05

In-Network Aggregation

If the network itself sums the workers' updates, each worker sends its gradient once and receives the sum once, instead of the 2(N−1)/N · B of a ring, and the switch does the adds.

worker 0 → slice of g0 worker 1 → slice of g1 … → switch: Σ in a slot of switch memory → sum multicast back to every worker

SwitchML (NSDI 2021)

  • Programmable switches (Barefoot Tofino, programmed in P4) aggregate model updates from many workers in the network (Sapio et al., “Scaling Distributed Machine Learning with In-Network Aggregation”, arXiv:1903.06701).
  • Reports up to 5.5× training speed-up on real-world benchmark models.
  • The switch pipeline does integer arithmetic, so workers convert floating-point updates to integers (with a scaling factor) before sending.
  • Limited switch memory and per-packet processing: the switch holds a small pool of aggregation slots that are reused as the update streams through, rather than the whole gradient.

NVIDIA SHARP

  • Performs reductions inside InfiniBand switches, offloading collective operations from the hosts to the network.
  • Same principle as SwitchML, in a fabric product rather than a research prototype.

The budget check

  • Summing two BF16 streams is 0.5 operations per byte (results.md section 2).
  • A QSFP56 module's budget is 0.40 to 3.96 operations per byte (section 1, on this series' reading of Kundu et al.'s “tens of GFLOPs” per link, arXiv:2608.21536): it fits at the high end, not the low.
The point for this series

Summing needs flows from many workers to meet. A pluggable module sees one link, one stream; the arithmetic would fit, but the operands are never in the same place. Aggregation belongs in a switch. What a link module could do to the data-parallel sync is transform or compress the single stream it carries, which is the rest of this deck.

06

Low-Communication Training: the DiLoCo Family

Instead of syncing every step, each worker (or island of accelerators) takes many local optimiser steps, then the workers exchange the pseudo-gradient, the change in their parameters, and apply one outer optimiser step to it.

DiLoCo, one outer step (after Douillard et al., Algorithm 1)
for each worker i, in parallel:
    θi ← θ                        # start from the shared parameters
    repeat H times: θi ← AdamW(θi, local data)   # inner steps, no communication
    Δi ← θ − θi                    # pseudo-gradient: one model-sized buffer
Δ ← all_reduce_mean(Δi)               # the only sync: once per H steps
θ ← Nesterov(θ, Δ)                  # outer step
MethodWhat it changesReported result
DiLoCo (Douillard et al., 2023, arXiv:2311.08105)Inner AdamW, outer Nesterov momentum; sync every H inner stepsOn C4 with 8 workers, matches fully synchronous training while communicating 500× less
Streaming DiLoCo (Google DeepMind, Jan 2025, arXiv:2501.18512)Syncs subsets of parameters in sequence, overlaps communication with training, quantises what is exchangedReduces required bandwidth by two orders of magnitude at similar quality
MuLoCo (May 2025, arXiv:2505.23725v1)Muon as the inner optimiser, plus error feedbackDelta compressed to 2 bits with next to no degradation; communicates 8× less than DiLoCo (figures from the v1 abstract)
SparseLoCo (Aug 2025, arXiv:2508.15706)Top-k sparsification of the pseudo-gradient (97–99% sparsity) with 2-bit quantisationLower final loss than dense DiLoCo, on models from 178M to 2B parameters
  • The sync is still one model-sized buffer, just rarer and smaller. The 2x, 8x and 85x columns of slide 04 size it: a 2-bit Llama-3-70B update over 100 GbE is 1,411.1 ms rather than 11,288.4 ms.
  • Every member of the family compresses at the endpoint, on the accelerator that holds the optimiser state. Error feedback, in particular, needs memory of what was not sent: state that a link module would have to hold per parameter if it did the compressing.
07

Frequency-Domain Gradient Compression

Sparsification usually keeps the largest gradient entries in their own domain. Wang et al. asked whether a transform first would keep more of the information at the same compression ratio (“FFT-based Gradient Sparsification for the Distributed Training of Deep Neural Networks”, HPDC 2020, doi:10.1145/3369583.3392681; preprint arXiv:1811.08596, titled “SuperNeurons: FFT-based Gradient Sparsification…”).

gradient, flattened to a 1-D signal → FFT → keep the largest coefficients (top-k) → range-based float encoding of the rest → send; inverse FFT at the receiver
  • The premise: the gradient's energy concentrates in fewer frequency coefficients than spatial entries, so the same number of kept values carries more of the signal.
  • Quantisation of what is kept uses a range-based floating-point representation, fitted to the span of the surviving coefficients, to cut the bits per value further.
  • Convergence: the authors prove convergence when the fraction of coefficients dropped is reduced during training, so the compression error shrinks as training proceeds.
  • Why it matters here: the expensive step is a transform. A photonic module's published operation set includes the FFT; top-k selection does not (it needs comparisons), which is the same split slide 09 meets in DeMo.
What a transform does not guarantee

Whether frequency coefficients are sparser than the raw entries depends on the tensor. Flattening a weight matrix's gradient into one long signal imposes an ordering the network does not care about; results.md section 5 shows that on white noise or sparse spikes a transform concentrates nothing. The case for frequency-domain compression is empirical, tensor by tensor.

08

DeMo: Decoupled Momentum and the DCT

DeMo (Peng, Quesnelle and Kingma; the later version adds Chen, Su and Liu; ICLR 2026; arXiv:2411.19870) drops the per-step all-reduce of full gradients. Each worker's momentum evolves locally, and only its fast-moving components are shared.

DeMo, one step on worker i (simplified from the paper's algorithm)
mi ← β mi + gi                    # local momentum, never all-reduced
C ← DCT(chunks(mi))                  # transform each fixed-size chunk
qi ← top_k(C)                       # keep the k largest per chunk: values + indices
mi ← mi − IDCT(qi)                  # remove what was sent: momentum is the error feedback
Q ← all_gather(qi)                    # the only communication: small
θ ← θ − η · IDCT(Q)                   # same update on every worker (see the paper for its exact form)
  • The momentum buffer acts as error feedback: what was not sent stays in mi and accumulates until it is large enough to be picked by top-k.
  • Reported: up to 85× less data per GPU than AdamW with DDP, at comparable loss and accuracy, for 300M and 1B-parameter models.
  • A DiLoCo-style variant (Nedelkoski et al., “Distributed Low-Communication Training with Decoupled Momentum Optimization”, NeurIPS 2025 DynaFront workshop, arXiv:2510.03371) decomposes Nesterov momentum into high- and low-frequency components with the DCT and synchronises only the high-frequency components every H steps, reporting up to 16× less communication than DiLoCo.
Why DeMo is this series' test case

Its compressor is a transform followed by a selection, applied to a stream on its way to the network. The transform is in a photonic module's operation set; the selection is not. That gap is the subject of the next three slides.

The Fixed-Band Experiment (Planned)

Status

This experiment is planned, not run. No results are shown, and none of the slides above depends on its outcome.

Train a small GPT, tens of millions of parameters (nanoGPT-style, on a small text corpus), four ways, at the same keep fraction in arms (b) to (d):

ArmOptimiser and compressionQuestion it answers
(a)AdamW with DDP, uncompressedThe baseline: loss with full communication
(b)DeMo as published: DCT + top-kReproduces the reference compressor at this scale
(c)DeMo with a fixed low-frequency band in place of top-kDoes a comparison-free selection keep the convergence?
(d)Fixed band with emulated optics: additive noise at a chosen ENOB, and the transform restricted to a native sizeDoes it survive analogue precision and a fixed transform length?
  • Metric: validation loss against bytes communicated, so arms with different compression are compared at equal traffic, not equal steps.
  • Sweeps: chunk size (for example 16 and 64, the two sizes costed in results.md section 2); keep fraction (for example 1/16, as in section 5); ENOB in arm (d), with noise added by the rule of the sister series (the noise rule for floating-point workloads).
  • Diagnostics: the share of each chunk's momentum energy that falls in the fixed band, logged during training, which ties the outcome back to section 5's synthetic cases.

Which band?

Low frequencies within a chunk are the obvious choice, and section 5 shows they work for smooth signals. But DeMo's own premise is that the components worth synchronising are the fast-moving ones, and the NeurIPS 2025 workshop variant (Nedelkoski et al.) synchronises the high-frequency components of momentum (slide 08). Is momentum energy within a chunk concentrated at low frequencies at all? And if what matters is high-frequency content, does a fixed high band do as well as top-k? The experiment should test a low band, a high band and top-k side by side rather than assume the answer.

From Convergence to Wall-Clock

The experiment gives loss against bytes. Whether that saves time depends on the system: link rates, latencies, how much of each sync overlaps with compute, and whether the module adds delay or energy. That question belongs to a discrete-event simulation, which is the part of this work that falls to a simulation engineer.

workers: inner steps → in-transit module: budget, latency, energy → cross-data-centre link → aggregate + outer step

What the model holds

  • Workers with a time per inner step and a sync interval H.
  • Links with bandwidth and latency, from the same presets results.md uses.
  • An in-transit module with an operations-per-byte budget, an added latency and an energy per byte; a kernel that exceeds the budget slows the link to the rate the module can sustain.
  • Sync policy: blocking, or streamed in parameter subsets and overlapped with training, as in Streaming DiLoCo.

What it reports

  • Wall-clock per outer step, and the share spent waiting on the link.
  • Link utilisation and energy per sync.
  • Time to a target loss, combining the experiment's loss-against-bytes curves with the simulated time per byte.
  • Calibration: compression ratios and loss curves from the experiment of slide 10; link presets from Disaggregated_Inference_Sim; the module's budget from results.md section 1.
  • Implementation: a SimPy model that extends Disaggregated_Inference_Sim with a training mode, so training and inference (deck 03) share one hardware description and cannot drift apart. Planned, not yet built.

13

What to Take Away

  • The data-parallel sync is the bulk transfer of LLM training: 16.06 GB of BF16 gradient for Llama-3-8B and 141.10 GB for Llama-3-70B, with a ring all-reduce sending 2(N−1)/N times that per worker.
  • Inside a cluster it is overlapped; across data centres it binds: 11.3 s per uncompressed Llama-3-70B update over 100 GbE (the interactive, slide 04).
  • Summing belongs in a switch. SwitchML and SHARP aggregate in the network; a link module sees one stream, so it can compress but not sum.
  • Low-communication training already cuts the traffic by orders of magnitude at the endpoint: DiLoCo 500×, Streaming DiLoCo two orders of magnitude in bandwidth, MuLoCo 2-bit deltas, DeMo up to 85× less data per GPU.
  • DeMo's compressor is half in a photonic module's operation set: the DCT is, top-k is not. A fixed frequency band is the comparison-free substitute, and it works only if momentum energy sits in the chosen band, which a planned experiment will measure.
  • Next: deck 03 turns to inference: KV hand-off between prefill and decode, weight streaming, and what a link module could do to them.
